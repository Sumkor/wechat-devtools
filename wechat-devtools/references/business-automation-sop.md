# 业务自动化 SOP

需要执行真实列表、搜索、详情、提交或跨页面业务流程时读取本文。

## 状态分层

不要把这些状态混为一谈：IDE 进程存在、项目窗口打开、项目已编译、9420 可连接、`currentPage` 非空、业务页数据就绪、业务登录有效。只报告已经有直接证据的最高层级。

## 通用流程

1. 确认 9420 属于目标项目，并读取当前路由；可复用时不再次执行 `auto`。
2. 优先读取 `app.json`、分包和 `tabBar`，再决定真实点击、`switchTab` 或 `navigateTo`。不要逐层猜 selector。
3. 关键动作前启动带 URL/method 过滤的标准 CDP 监听；收到 ready 后再执行一次动作。
4. 动作后先确认路由，再读取一个关键元素或局部 page/component data，最后核对目标请求和最小响应字段。
5. 需要视觉证据时最后截图；同一事实已有充分证据后不要重复抓取整页 data、元素树和响应体。

## 页面 data、组件 data 与网络响应

`page.data()` 和组件 `data()` 读取的是业务映射到运行时的数据，不是原始接口响应。字段可能被裁剪、改名、合并分页，或只保存在组件、状态管理库、闭包、插件、原生组件或 WebView 内。

推荐顺序：

1. 读取明确的 page data 局部路径。
2. 读取承载列表或状态的精确组件 data。
3. 搜索请求方法、`setData`、状态映射和点击回调，建立“接口字段 → 运行时状态 → 路由参数”的映射。
4. 需要原始响应时使用标准 CDP；只读取完成任务所需字段。

页面/组件 data 没有目标字段，不能据此断言接口没有返回。

## 重组件、瀑布流和虚拟列表

- 优先使用稳定 class、id、组件标签和 `u-r`/明确 ref；不依赖动态索引或运行时生成 ID。
- `page.$`/`page.$$` 不保证穿透自定义组件。最多进行一次精确 Page selector 尝试，随后查询组件宿主并逐层进入已确认的子组件。
- 不先运行宽泛的 `view`、`input` 或通配整树查询；这可能长时间占用 Automator 串行通道。
- 不把接口数组下标映射成瀑布流列号、DOM 顺序或固定滚动距离。使用稳定业务 ID、可见文本和源码路由逻辑交叉确认。
- 已确认点击仅负责拼接详情路由时，用户任务允许可用官方 `navigateTo` 作为等价路径；若点击包含权限、状态写入或其它业务副作用，必须继续真实点击，不能绕过。

## 手势和滚动

- 通用滑动使用元素 `touchstart/touchmove/touchend` 组成触摸序列。
- 只有目标确为 `scroll-view` 时才使用 `ScrollViewElement.scrollTo(x, y)`。
- 滚动后读取可见文本或截图，以小步长继续；不要用固定大距离碰运气。

## 断言和等待

推荐确认顺序：目标路由 → 关键元素或局部 data → 目标接口 → 最终截图。

- `tap`、`navigateTo` 或 `switchTab` 返回不等于页面完成加载。
- Automator 超时也不等于动作一定失败；动作可能已发送。先复核路由、元素和请求，再决定是否重做。
- 对路径、可见性、文本和 data 使用短周期条件轮询，不用固定长 sleep。
- 页面动作保持串行；不要让多个 Agent 或脚本并发控制同一 9420。

## 快速恢复

1. 点击结果不明确：先读当前路由和目标请求，不立即重复点击。
2. 当前路由异常：结合 page stack 与 `app.json`，选择 `switchTab`、`navigateTo`；不要把 `reLaunch` 当通用恢复手段。
3. selector 穿透失败：改查组件宿主、源码和业务后置条件，不使用坐标猜点或 evaluate 伪造事件。
4. 页面上下文重建：重新取得 `currentPage` 和元素句柄；旧句柄不要复用。
5. 9420 命令持续排队：确认没有其它控制者后只断开并重新附着 Automator；不要因此重启 IDE 或重复 `auto`。

## 安全边界

真实授权、支付、绑定/解绑、删除、提交和账号切换等动作必须满足用户授权和可逆性要求。不得通过 mock、`setData`、evaluate 内部 handler、伪造事件或迁移 token 冒充正常业务结果。手机号授权边界见 [getPhoneNumber 真实授权边界](get-phone-number-auth.md)。
